## Проблема

Когда препарат выбран из каталога (`treatment_catalog`), в рецепт подтягиваются `inn_snapshot` (латынь) и `form_snapshot`. Если врач вписал название от руки:

- `medication_latin_name` = русское название (в `Rp:` печатается по-русски и без падежа),
- `dosage_form`, `dose`, `frequency`, `duration`, `D.t.d.` остаются пустыми.

То же в «Выписать рецепты» из назначений визита (`WriteRxFromAssignments`) — там вообще только грубый regex-парсер строки.

## Что сделаю

1. **Новая Edge Function `rx-normalize-items`**
   - Вход: массив «сырых» позиций (название + всё, что известно: доза, кратность, длительность, свободный текст назначения).
   - Шаг A — детерминированный поиск: сопоставление названия с `treatment_catalog` (точное, регистронезависимое, затем `ILIKE`/триграммное «похожее») и с `medication_digests.medication_name` / `synonyms`. Если найдено — берём латынь/форму/дозировки из базы, без AI.
   - Шаг B — для ненайденных: один AI-вызов (Gemini 2.5 Flash) с промптом уровня рецептурной грамматики: латинское наименование в правильном падеже (`Tabulettas Tamsulosini 0,4`, `Solutionis ... 1 % — 5 ml`), `dosage_form`, `dose`, `quantity` (D.t.d. на курс, считая из кратности и длительности), `frequency`, `duration`, `signa`, плюс `confidence` и `source`.
   - Результат кэшируется в `medication_digests` (добавляю поля для латыни/формы/типичной дозы), чтобы второй раз препарат не гонять через AI.
   - Доступ только admin/editor, как в остальных Rx-функциях.

2. **Миграция**: добавить в `medication_digests` колонки `latin_name`, `dosage_form`, `default_dose`, `default_frequency`, `atc_code` (nullable) — кэш нормализации. Схема таблицы, GRANT'ы и RLS не ломаются.

3. **`planToRx.ts`**: помечать позицию флагом `_needsLookup`, когда `inn_snapshot`/`form_snapshot` пусты или латынь совпадает с русским названием (кириллица в `medication_latin_name`).

4. **`RxItemsPreviewDialog`**: 
   - при открытии автоматически догоняет нормализацию для позиций с `_needsLookup` (спиннер на строке);
   - бейдж «из каталога» / «уточнено ИИ (проверьте)» — жёлтый для AI, чтобы вы контролировали латынь;
   - кнопка «Уточнить» на каждой строке и «Уточнить все» для повторного запроса;
   - все поля остаются редактируемыми, ничего не перезаписывается без вашего ведома после ручной правки.

5. **`WriteRxFromAssignments`**: заменить regex-парсер на тот же `rx-normalize-items` (строка назначения целиком уходит в нормализацию), результат — в общий `RxItemsPreviewDialog` вместо самодельного диалога, чтобы поведение из визита и из плана лечения было одинаковым.

6. **Защита печати**: если после нормализации `medication_latin_name` всё ещё кириллица — предупреждение в диалоге и в форме рецепта («латинское наименование не заполнено»), чтобы бланк не уходил на печать по-русски.

## Технические детали

- Кэш-ключ — нормализованное имя (lower, trim, без дозы/формы).
- AI вызывается пакетом (все ненайденные позиции одним запросом) — 1 вызов на выписку.
- Ошибка/лимит AI не блокирует выписку: поля остаются пустыми, показывается toast, ручной ввод работает как сейчас.
- Файлы: `supabase/functions/rx-normalize-items/index.ts` (новый), `src/lib/treatment/planToRx.ts`, `src/lib/prescriptions/normalizeRx.ts` (новый клиентский хелпер), `src/components/cabinet/RxItemsPreviewDialog.tsx`, `src/components/visits/WriteRxFromAssignments.tsx`.
