# Оценка и распознавание длинных документов

## Уже выполнено
Публикация готовой справки запрошена для https://tarusin-professor-site.lovable.app. Три теста справки повторно пройдены. Завершение выкладки не подтверждено.

## Порядок работы
1. После выбора документа и нажатия «Распознать» сначала показать «Оцениваю документ». До завершения оценки не отправлять документ на распознавание ИИ.
2. Для PDF проверить число страниц, текстовый слой, объём текста по страницам и размер файла. Для Word/RTF/ODT/текста оценить объём извлечённого текста. Для изображений проверить размер и разрешение.
3. Если оценка не выполнена (например, PDF повреждён или защищён паролем), показать ошибку, а не считать документ коротким.
4. Если документ укладывается в безопасный объём, автоматически перейти к обычному распознаванию.
5. Если не укладывается, показать «Требуется фрагментация», число страниц/объём и причину. Не отправлять исходный длинный документ целиком.
6. Предлагаемый вариант после предупреждения: кнопка «Разделить и распознать». Обрабатывать фрагменты последовательно, показывать прогресс и давать остановить дальнейшую обработку. Остановка ожидания не гарантирует прекращения уже отправленного вызова ИИ.
7. Сохранять результаты частей отдельно с номерами исходных страниц и датами. Не терять готовые части при ошибке следующей; повторять только ошибочную часть по команде пользователя. При неполном распознавании явно указать пропущенные страницы.
8. Перед добавлением в анамнез сохранить существующую проверку принадлежности пациенту и редактирование результата; текущие поля осмотра не перезаписывать. Для импорта старого протокола оставить существующее окно проверки, не объединять конфликтующие поля разных фрагментов молча.

## Предлагаемые границы для согласования
- Сканированный PDF: не более 3 страниц на один вызов.
- Текстовый PDF: не более 6 страниц и 15 000 символов на один вызов.
- Word/RTF/ODT/текст: не более 15 000 символов на один вызов; длинные абзацы тоже разделять без потери текста.
- Смешанный PDF: применять ограничение сканов, если хотя бы одна страница не имеет достаточного текстового слоя.
- Это консервативная оценка нагрузки, а не гарантия времени ответа модели. Существующий предел выбора файла 20 МБ не увеличивать.

## Технический объём
- Новые локальные помощники в `src/lib/visits/` для оценки нагрузки и последовательной подготовки фрагментов, с тестами правил границ и сохранности страниц/текста.
- `src/lib/visits/protocolImport.ts`: обязательная оценка перед вызовом распознавания и передача сигнала остановки только для этого запроса; не менять общую сетевую конфигурацию.
- `src/components/visits/HistoryDocumentsDialog.tsx`: состояние оценки, сообщение о фрагментации, прогресс и остановка.
- `src/components/visits/ProtocolImportDialog.tsx`: та же оценка для импорта старых документов, без молчаливой потери частей.
- `AGENTS.md`: одно правило об общей предварительной оценке документов.
- Использовать уже установленный `pdfjs-dist`, без новых зависимостей. PDF со сканами готовить постранично; текст извлекать только при полноценном текстовом слое, иначе распознавать изображение страницы.
- Не менять базу, серверные функции, CORS, failover, Vite, авторизацию, галереи и защищённые файлы.
- До применения кода показать полный точный diff и дождаться «Подтверждаю», как требует установленный порядок проекта.

## Проверки
- На исходном PDF из 18 сканированных страниц оценка должна потребовать фрагментацию до первого вызова ИИ.
- Короткий документ проходит оценку и сразу распознаётся.
- Проверить границы размеров, текстовый и смешанный PDF, повреждённый/защищённый PDF.
- Проверить реальный вызов ИИ для части, прогресс, остановку ожидания, ошибку части и повтор без повторной отправки готовых частей.
- Проверить сохранность номеров страниц, дат и текста, принадлежность пациенту, применение в анамнез, сохранение и повторное открытие визита.
- Проверить отсутствие изменений защищённых файлов и соответствие согласованному diff.
