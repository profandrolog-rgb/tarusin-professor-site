# Замеры доступности сайта и бэкенда из Казахстана

Цель: понять, доступны ли посетителям из Казахстана сам сайт и, главное, маршруты бэкенда (авторизация, база, функции). Без развёртывания серверов и без изменений в коде.

## Что делаем

1. **Пробы с казахстанских узлов (бесплатно).**
   Через распределённый пробник (узел Алматы, дополнительно Бишкек/Ташкент как соседние сети) проверяем:
   - `https://tarusin.pro/` — отдаётся ли страница;
   - `https://api2.tarusin.pro/auth/v1/health` — основной маршрут бэкенда;
   - `https://api3.tarusin.pro/auth/v1/health` — резервный маршрут;
   - прямой домен бэкенда — для понимания, блокируется ли он в KZ, как в РФ.
   Смотрим три параметра по каждому адресу: устанавливается ли TLS, какой HTTP-код, сколько миллисекунд.

2. **Разбор результатов.**
   Три возможных вывода:
   - всё отвечает 200 — из KZ проблем нет, дополнительные серверы не нужны;
   - сайт открывается, но api2/api3 рвутся на TLS — нужен прокси в KZ-достижимой локации;
   - не открывается ничего — вопрос к DNS/хостингу, а не к бэкенду.

3. **Заключение с оценкой стоимости.**
   Если по результатам понадобится KZ-прокси — отдельным шагом (после вашего решения) готовим конфиг nginx + Let's Encrypt для поддомена `api4.tarusin.pro` и только потом добавляем его в переменные окружения как альтернативный маршрут.

## Чего в этом шаге НЕ делаем

- Не создаём draft/клон проекта.
- Не заказываем и не настраиваем серверы.
- Не меняем код, переменные окружения, маршруты API и failover.
- Не публикуем и не запускаем деплой.

## Стоимость и трудозатраты

| Вариант | Деньги | Работа |
|---|---|---|
| Замеры с внешних узлов (этот план) | 0 ₽ | ~15 минут, полностью на моей стороне |
| KZ-прокси `api4.tarusin.pro` (если понадобится) | ~300–900 ₽/мес за VPS, домен и SSL бесплатно | ~40–60 минут ваших действий, конфиг готовлю я |
| Полное зеркало сайта на KZ-сервере | ~700–1200 ₽/мес | 2–3 часа + поддержка второго деплоя |

## Технические детали

- Пробники дают сетевую картину (DNS → TCP → TLS → HTTP), но не эмулируют браузер: ошибки уровня JS, куки и сторонних скриптов так не выявляются.
- Маршрутный контракт остаётся неизменным: preview-хосты `*.lovable.app` → `api3`, рабочий сайт → `api2`.
- Никаких изменений в `backendEndpoints.ts`, `backendRouteManager.ts`, `backendFailover.ts` в рамках этого шага.
